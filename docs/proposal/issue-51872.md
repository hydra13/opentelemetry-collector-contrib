# Issue #51872: propagate the Azure Data Explorer ingestion context

This document records a fork-only implementation proposal for
[open-telemetry/opentelemetry-collector-contrib#51872](https://github.com/open-telemetry/opentelemetry-collector-contrib/issues/51872).
It is working material for validating the change before a human contributor discusses it with the
upstream maintainers. It is not intended to be included in the upstream pull request or copied into
an issue comment or pull request description.

## Problem

The Azure Data Explorer exporter configures `exporterhelper` timeout handling for metrics, logs, and
traces. Each exporter callback therefore receives a context carrying the per-attempt deadline and
parent cancellation. The callbacks eventually call `ingestData`, but that helper currently invokes
`Ingestor.FromReader` with `context.Background()`. The substitution drops both the deadline and
cancellation immediately before the SDK boundary.

Because all three signal paths share `ingestData`, the configured timeout can be ignored for metrics,
logs, and traces.

## Intended behavior

- Pass the exporter callback context unchanged to `Ingestor.FromReader`.
- Apply the same behavior to metrics, logs, and traces.
- Return a cancellation or deadline error produced by the ingestor to `exporterhelper`.
- Do not create a timeout inside the Azure Data Explorer exporter.
- Preserve `timeout: 0`: a caller context without a deadline remains without an exporter-created
  deadline, while parent cancellation still propagates.
- Keep the existing empty-payload behavior, which avoids calling the ingestor.

## Proposed implementation

1. Add `context.Context` to the private `ingestData` helper.
2. Replace the helper's `context.Background()` argument with the supplied context.
3. Pass each callback's context from `metricsDataPusher`, `logsDataPusher`, and
   `tracesDataPusher` to `ingestData`.
4. Avoid unrelated changes to configuration, retry, queue, serialization, and SDK setup.

## Regression tests

Use the existing mock ingestor as the Azure SDK boundary. Add focused table-driven coverage for all
three signal callbacks:

- a context value supplied to the callback is visible at `FromReader`;
- a canceled callback context is visible at `FromReader`, and `context.Canceled` is returned to the
  callback caller;
- the tests use no sleeps or wall-clock timeout assumptions.

The context-value test also uses a context without a deadline, demonstrating that propagation does
not manufacture one for the `timeout: 0` case.

## Expected fork diff

The transferable solution should contain only:

- `exporter/azuredataexplorerexporter/adx_exporter.go`;
- `exporter/azuredataexplorerexporter/adx_exporter_test.go`;
- one `.chloggen` bug-fix entry for issue `51872`.

This proposal file should remain in the validation fork. A future contributor can cherry-pick only
the separate solution commit after the implementation direction is accepted upstream.

## Upstream questions for the human contributor

Before opening an upstream pull request, the human contributor should write their own issue comment
and obtain maintainer agreement on:

- propagating the callback context unchanged rather than creating a component-local timeout;
- covering metrics, logs, and traces in one focused change;
- treating newly honored deadlines as the intended correction to existing timeout behavior;
- preserving `timeout: 0` through the absence of a component-created deadline.
